# RouterOS `/app` YAML manifests

TikBook adds VS Code support for RouterOS `/app` YAML manifests using schemas generated by `tikoci/restraml`. The built-in support covers schema associations, native completions/hover/inlay hints, scaffold commands, and low-noise RouterOS-specific diagnostics. The same schemas can also be used manually with the Red Hat YAML extension.

This is a native editor integration, not a full browser clone of `tikapp.html`; WebMCP, share/import/download controls, and built-in app browsing remain future work.

## Requirements on RouterOS

Custom `/app` YAML is for RouterOS 7.22+. The `/app` command tree starts in 7.21, but custom YAML creation is 7.22+ work.

Before deploying an app to a router, check:

- `container` extra package is installed;
- container device-mode is enabled when the app needs container support, especially `devices:` mappings;
- device architecture is supported for the image and feature scope (`arm64` or `x86` are the first target architectures);
- external storage is available or strongly considered for images, layers, and persistent volumes;
- RAM is adequate for the selected containers.

RouterOS `/app` YAML is similar to docker-compose, but it is not docker-compose. Avoid unsupported compose keys such as `deploy:` and do not add a top-level `version:` key unless RouterOS documentation later requires it.

## File naming triggers

TikBook schema associations intentionally avoid matching every generic `app.yaml` file in a workspace.

Single-app manifest patterns:

- `*.tikapp.yaml`, `*.tikapp.yml`
- `*.app.yaml`, `*.app.yml`
- `**/{app,apps,tikapp}/app.{yaml,yml}`

App-store manifest patterns for `app-store-urls=` files:

- `*.tikappstore.yaml`, `*.tikappstore.yml`
- `*.appstore.yaml`, `*.appstore.yml`
- `**/{app,apps,tikapp}/app-store.{yaml,yml}`

Use `.tikapp.yaml` and `.tikappstore.yaml` for new files when possible; they are the clearest and least likely to conflict with other tooling.

## YAML extension dependency

Schema validation and most YAML completions come from Red Hat YAML (`redhat.vscode-yaml`). TikBook should recommend it, but the YAML extension owns parsing and JSON Schema validation. If it is missing, `/app` YAML files still open as text/YAML, but schema validation and schema-driven completions will be absent.

## Schema variants

`restraml` publishes separate schemas for editing and strict validation.

| Manifest type | Editor-friendly schema | Strict/latest schema |
|---|---|---|
| Single app | <https://tikoci.github.io/restraml/routeros-app-yaml-schema.editor.json> | <https://tikoci.github.io/restraml/routeros-app-yaml-schema.latest.json> |
| App store | <https://tikoci.github.io/restraml/routeros-app-yaml-store-schema.editor.json> | <https://tikoci.github.io/restraml/routeros-app-yaml-store-schema.latest.json> |

Use editor schemas while writing files in VS Code. They intentionally relax some regex patterns so completions remain useful. Use strict schemas for CI, review, or final validation before publishing an app/store.

## Manual VS Code configuration

TikBook contributes schema associations automatically for the file patterns above. Add this to VS Code settings only if you want to customize or broaden workspace/user-level validation:

```json
{
  "yaml.schemas": {
    "https://tikoci.github.io/restraml/routeros-app-yaml-schema.editor.json": [
      "*.tikapp.yaml",
      "*.tikapp.yml",
      "*.app.yaml",
      "*.app.yml"
    ],
    "https://tikoci.github.io/restraml/routeros-app-yaml-store-schema.editor.json": [
      "*.tikappstore.yaml",
      "*.tikappstore.yml",
      "*.appstore.yaml",
      "*.appstore.yml"
    ]
  }
}
```

For a single file, use a YAML language-server header instead:

```yaml
# yaml-language-server: $schema=https://tikoci.github.io/restraml/routeros-app-yaml-schema.editor.json
name: hello-nginx
services:
  web:
    image: nginx:alpine
    ports:
      - "8080:80/tcp"
```

For final strict validation, switch the header to the strict schema:

```yaml
# yaml-language-server: $schema=https://tikoci.github.io/restraml/routeros-app-yaml-schema.latest.json
```

Be aware that strict schemas can reduce inline completion quality because regex patterns on port strings and environment-variable names limit what the YAML extension can suggest.

## App-store manifests

An app store file is a YAML array of app definitions, not a single object:

```yaml
# yaml-language-server: $schema=https://tikoci.github.io/restraml/routeros-app-yaml-store-schema.editor.json
- name: hello-nginx
  services:
    web:
      image: nginx:alpine
      ports:
        - "8080:80/tcp"
```

Use store schemas only for files intended for RouterOS `app-store-urls=`. Use the single-app schema for one custom app manifest.

## Strict schema guidance

- Prefer editor schemas while authoring.
- Prefer strict schemas in CI or pre-release checks.
- Do not mix old slash-style and newer colon-style port formats inside one port string.
- Treat schema success as necessary but not sufficient: RouterOS version, package, device-mode, storage, architecture, and image availability still decide whether deployment succeeds.
